# 웹 카툰 공간의 따뜻한 분위기

목표는 화면 전체를 노랗게 물들이는 것이 아니라 따뜻한 직사광, 차분한 그늘, 읽기 쉬운 형태와 공간 구도를 만드는 것이다. 기존 일본 애니메이션/카툰 아트 방향과 플레이 기능을 유지한다. 분석만 요청하면 변경하지 않고 근거와 수정안을 제시한다.

## 먼저 확인할 것

- 실제 실행 화면과 사용자가 준 참고 이미지, 프로젝트 DESIGN.md를 확인한다. 분위기 차이를 색, 명암, 재질, 카메라, 공간 밀도로 나눠 판단한다. 관찰과 추측을 구분한다.
- 현재 렌더러의 색 공간, tone mapping, 노출, 광원, 그림자와 재질을 읽는다. GLB의 KHR_materials_unlit / MeshBasicMaterial은 빛에 반응하지 않으므로 광원만 바꿔 해결했다고 판단하지 않는다.
- 사용 가능한 원본 텍스처 목록을 확인한다. 임시 Canvas 패턴이 생성된 색 맵을 대신하고 있으면 관련 에셋을 직접 열어 적용 여부를 판단한다. 생성 텍스처를 seamless라고 가정하지 않는다.
- 유리, 발광, 식생의 알파, 윤곽선, 캐릭터 전용 셰이더를 식별한다. 모든 표면을 한 재질로 일괄 변환하지 않는다.

## 원본과 파생본

- 원본 모델과 텍스처 파일을 덮어쓰지 않는다. 파일 편집이 필요하면 별도 파생 경로에 복사하고 출처를 기록한다.
- 런타임 작업이면 씬을 복제하고 별도 파생 재질을 할당한다. 읽기 전용 geometry와 이미지 데이터는 공유해도 된다. 원본 material 및 loader cache를 mutate하지 않는다.
- texture의 반복/offset/colorSpace를 변경할 경우 Texture 객체를 복제한다. 반복 배치에는 파생 재질을 재사용하고 공유 리소스를 개별 인스턴스에서 dispose하지 않는다. 캐시 수명과 소유권에 맞춰 해제한다.
- 원본 보존과 런타임 복제는 파일 복사 작업과 구별해 보고한다. 웹 재질만 바꿨다면 Blender 파일을 수정했다고 말하지 않는다.

## 조정 방법

1. **빛과 그림자의 색 관계:** 크림색 계열의 방향광과 옅은 푸른 하늘광을 출발점으로 삼는다. 측면광으로 지붕/기둥의 그림자가 공간 구조를 보여주게 한다. 그늘은 검정으로 뭉개지지 않고 재질색이 읽혀야 한다. 아래쪽 보조광은 장면에 맞춰 절제한다.
2. **카툰 명암:** 무광 건축물에는 기존 색 맵을 유지하는 MeshToonMaterial과 nearest-filtered 2~3단계 gradient를 검토한다. Three.js gradient는 법선·광원 각도에 따른 직접광 반응을 단계화하는 것이며 최종 픽셀 색 수를 제한하지 않는다. 환경광/다중 광원/그림자도 결과에 영향을 준다. 구운 음영 위에 추가 명암이 너무 강하면 먼저 대비를 낮춘다. 광택이나 강한 normal map을 추가해 찰흙처럼 보이게 하지 않는다.
3. **예외 재질:** 윤곽선의 면 방향과 culling을 유지하고 별도 그림자 투사를 피한다. 유리·발광·알파 cutout은 원래 의도를 보존한다. 재질 변환 시 map, color, side, alphaMap/alphaTest, opacity, vertex colors 등 실제 사용 속성을 확인한다.
4. **국소 온기:** 벽등은 필요한 위치에만 소수의 따뜻한 광원을 둔다. 발광 표시만으로 주변 표면이 밝아지지는 않는다. 광원 거리/감쇠를 제한하고 하얗게 날아가는 영역을 확인한다. bloom은 필수가 아니다.
5. **카메라와 공간:** 필요할 때만 거리, pitch, 주시 높이, FOV를 함께 조정한다. 바닥만 내려다보지 않고 캐릭터 너머로 공간이 이어지게 한다. 문·목표물·이동 경로의 가독성을 우선한다. 공통 카메라 코드를 쓰면 허브별 옵션을 추가해 다른 게임 화면의 기본값을 유지한다.
6. **바닥:** 실제 색 맵이 있다면 적정 월드 크기로 매핑하고 sRGB와 사선 필터링을 설정한다. 이음새를 실제 반복 화면에서 확인한다. MirroredRepeat는 색 단절을 줄이는 선택지지만 줄눈 반전과 타일 길이 변화가 생길 수 있으므로 완전한 seamless 보정으로 보고하지 않는다.

수치나 색을 프로젝트마다 그대로 복사하지 않는다. 재질과 조명만으로 충분하면 메시 수정, 신규 에셋, NPC, 후처리 라이브러리로 범위를 넓히지 않는다.

## 검증과 완료

- 기본 카메라에서 전후를 비교한 뒤 사선/확대 화면으로 과노출, 어두운 뭉침, 반복 경계, 그림자 acne, 윤곽선 중첩, 알파 손상을 확인한다. 조명 비교는 가능한 한 동일 카메라에서 하고 구도 변경은 별도로 평가한다.
- 회전·줌·원위치 복원과 주요 상호작용 접근을 확인한다. 카메라/조명 공유로 다른 화면까지 바뀌지 않았는지 확인한다.
- 프로젝트의 빌드/타입 검사를 실행한다. 이동/충돌/게임 로직을 건드렸으면 관련 테스트도 실행한다. 재질 수, 추가 광원, 그림자 비용의 증가를 살피고 측정 없이 성능 개선을 주장하지 않는다.
- DESIGN.md가 있으면 선택한 렌더링 방식, 원본/파생본 관계, 알려진 한계를 반영한다.
- 실제 화면에서 목표한 온도 대비와 가독성이 확인되고 검사가 통과하면 완료한다. 바꾼 레이어(파일/런타임 재질/빛/카메라), 보존한 원본, 검증 결과와 남은 시각적 한계를 짧게 보고한다.
